Milestones

Each milestone shipped with its own regression suite; nothing merges unless every earlier suite stays green.

  1. ✓

    M1 — Prototype + test foundation

    6 suites · 40 tests

    Single-file app covering the whole core loop — mock auth, swipe deck, match modal, chat with auto-replies, filters, profile — verified end to end in phone-emulated Chromium; spec pack landed in docs/spec/, repo organized around one-feature-one-suite.

  2. ✓

    M2 — Safety (spec P0)

    + test-safety.js (11)

    Report (six-reason picker, confidentiality note, 24-hour moderation commitment, optional also-block) and block from every surface showing another user: deck card, match row, chat header. Immediate, both directions, permanent.

  3. ✓

    M3 — Settings & compliance (spec P0)

    + test-settings.js (10)

    Settings screen: preferences shortcut, persisted notification toggle, ToS + Privacy Policy (also linked at signup), support contact, full data export, logout, and real in-app account deletion behind an explicit confirmation.

  4. ✓

    M4 — Profile photos + moderation

    + test-photos.js (10)

    Six-slot grid with reorder; new photos sit “In review”, then approve or reject (deterministically demonstrable); rejection dots the Profile tab; other users only ever see approved photos — cards fall back to initials.

  5. ✓

    M5 — API contract, implemented

    + test-api.js (13)

    02-api-contract.md built as an in-page mock backend — error envelope, rotating tokens, OTP throttling, idempotent swipes, cursor pagination, WS frames — and the UI rebuilt onto it: phone OTP onboarding, server-enforced 18+ stop, gender preferences, presigned photo flow, unmatch, read receipts.

  6. ✓

    M6 — Reference Go backend + remote transport

    + test-server.js (13)

    server/ implements the same contract over real HTTP + WebSocket (in-memory store, bot engine, moderation timers) and serves the client; the client probes /v1/healthz at boot and switches transports. Conformance re-run against the real server; the served client driven over a live socket.

  7. 7

    M7 — Native SwiftUI client

    queued

    Per 09-ui-build-plan.md, against the Go server — needs an Xcode environment. Spec files 03–09 also still to land in docs/spec/.

Known gaps & next steps

  • Contract edges not yet surfaced: the banned account wall, the deck's rate_limited interstitial, and visible WS offline/reconnecting states.
  • Spec files 03–09 (data models, design system, flow specs, build plan) still to be dropped into docs/spec/.
  • Persistence: the Go store is in-memory by design — Postgres/Redis/S3 swap in behind the existing route handlers.
  • M7: the native SwiftUI client against the Go server, once an Xcode environment is available.
